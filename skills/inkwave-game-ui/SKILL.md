# Inkloom · 墨织

Inkloom（墨织）是受 INKWAVE 启发的自适应游戏 UI 技能，技术调用名继续使用 `inkwave-game-ui`。先理解游戏，再设计并完成目标项目的界面改造。用户只调用本技能时，默认覆盖项目已有的菜单、HUD、设置、暂停和结算；保留玩法和业务接口，不凭空增加联机、商店、武器、货币或进度系统。

## 先分析游戏，形成设计判断

优先使用当前项目，读项目约定、用户设定、设计文档、现有美术/截图、玩法代码、UI场景、输入与状态流；识别引擎和运行方式。仅在找不到可用项目时询问目录。先看能运行的旧界面，复用主题、框架、事件和存档接口。

必读 [自适应设计决策](references/adaptive-design.md)。以项目证据回答：题材/世界观是什么、希望玩家有什么情绪、核心循环和高频操作是什么、哪些信息影响即时决策、主要设备/视角是什么、已有颜色语义与品牌约束是什么。区分明确设定和推测；未知处采用可逆假设，不编造世界观或改变规则。

在现有设计记录或简短工作说明中明确本项目的颜色角色、信息层级与布局、预览/提交/取消语义、动效强度，以及这些选择的游戏依据；然后继续实现，无需等待逐项批准。小任务只分析相关部分。设计判断由调用本技能的Codex完成，运行时主题函数仅应用已决定的参数，不会自行理解游戏。

以下是可借用的信息组织方式，位置/比例/密度按游戏重新决定；只实现已有或任务需要的屏幕：

| 目标需求 | INKWAVE 原型 |
|---|---|
| 主菜单 | 主次行动分级、必要资料/当前配置、保留场景；导航可侧置、居中或底部 |
| 关卡/模式选择 | 票券/地图/节点与预览建立对应，配置与开局路径简短 |
| 装备/技能/角色选择 | 卡片、属性比较、实时预览；按内容与设备决定网格/列表/抽屉 |
| 设置 | 分页、胶囊分段、圆滑杆、大开关、上下文解释与反馈 |
| 战斗 HUD | 围绕即时决策分级，保护准星/棋盘/角色/对白等核心区域；资源/危险/能力语义化反馈 |
| 暂停 | 操作与必要状态摘要；离线暂停与在线继续运行按现有玩法处理 |
| 结算 | 先结果和角色，后数据、奖励；首次确认跳过计数，后续确认执行按钮 |
| 已有联机大厅 | 不透明双描边贴纸、队色名牌、荧光行动色、房主与访客权限提示 |

## 读取规则

- 按需读 [视觉与源码剖析](references/source-analysis.zh-CN.md) 的相关页面/视觉章节获取原作证据和局限；它记录原作，项目设计由自适应决策确定，不能把原作配色/位置当成项目限制。
- 实现输入、预览、动效或状态切换时读 [交互规范](references/interaction-spec.md)，不要只改 CSS/Theme 颜色。
- 按当前引擎读 [引擎适配](references/engine-adapters.md) 对应章节；收尾用 [验收清单](references/acceptance.md)。
- [设计参数](assets/inkwave.tokens.json) 中source是冻结的原作参考，adaptation是迁移规则；项目值按分析生成。原作五组配色、深紫面板、荧光行动色、16:9位置和动效幅度都可调整。参考 [项目主题示例](assets/theme-profile.example.json)，按实际需求创建项目主题。源码已离线保存，无需每次重新克隆。
- 需要视觉对照时查看 `references/screenshots/`；这些是原仓库 UI Lab 的实拍，背景/角色可能是实验室占位，不是完整游戏实机截图。

## 保持风格的六条规则

1. **形状与字重先于配色。** 胖标题、深墨色粗描边、白切边、硬偏移投影、小角度倾斜、胶带和少量滴墨组成可触摸的印刷物。正文清晰端正，不给所有小字加粗描边。
2. **两种材质形成层级。** 信息承载面板与重点实体贴纸区分；面板可用符合世界观的有色玻璃、深墨或印刷纸感，保持墨色结构、切边与硬影。面板色、透明度和网点强度按场景可读性与性能调整。
3. **颜色由语义和题材决定。** 可从现有美术/世界观提取全新色系；定义surface/text/muted/primary/secondary/action/focus/danger等角色，按需加阵营/资源色。原作五组仅作可选参考，不默认套橙蓝，不强制双色阵营、深紫或荧光黄绿。主题色与警告语义冲突时用背景、明度、图标、文字和层级解开，检验真实背景上的对比。
4. **所有输入共享状态。** 鼠标悬停、键盘和手柄导航进入同一 focus 状态；selected/equipped 持久，focus 临时，两者独立。按下挤压、松开回弹、越界轻撞；触屏不依赖 hover。
5. **预览不等于提交。** 焦点更新说明和对比；确认才改装备/角色。设置即时反馈并按项目约定保存。保留已装备、比较、已保存的明确标识。
6. **动效强度服务玩法与情绪。** 保留清楚的墨水/印刷反馈与触感，按阅读、精确操作、紧张或庆祝场景选择幅度、过冲、时长和频率。叙事/恐怖可用短距离低过冲，竞技可鲜明但让即时反馈立刻出现，经营可降低高频循环。原作参数是参考；重要转场才用泼墨，减少动态仍保留状态反馈。

## 实施

把分析所得的角色色、尺寸/锚点与动效参数写进项目主题，再改共享 Button、Card/Ticket、Panel、Tabs、Toggle、Slider、Prompt、Toast 和资源条，并应用到页面。布局与流程需要改动时修改相应组件/场景，不能只注入几个颜色变量。保留游戏标题、角色、美术、文案、数据和业务回调；装饰使用目标符号或抽象墨点，不默认复制原作品牌与角色。

Web可适配复制 `assets/web/inkwave-ui.css` 与 `assets/web/inkwave-ui.mjs`，用applyInkTheme(root,theme)应用自定义语义颜色与动效；setInkPalette仍支持任意两种十六进制颜色，inkPalettes仅是研究参考。预览有世界观衍生主题和自定义颜色示例，它们不限制后续设计。基础实现含键鼠反馈、动作/声音钩子与清理，未内置手柄轮询、地图或结算，须接项目已有系统。复制CSS连同fonts或修改路径；派生代码保留assets/INKWAVE-LICENSE.txt，字体保留OFL。

用 `python scripts/serve-preview.py` 启动附带样例，打开终端输出的本地地址；此脚本只绑定127.0.0.1，并为Windows补齐模块MIME类型。直接用file://打开HTML可能因ES模块限制无法交互。端口占用时传 `--port 8494` 等空闲端口。

中文采用项目可用的粗黑/圆黑，标题900、较小描边和适当行高；Titan One/Rubik 的 Latin 子集不含汉字。没有合法中文字体资产时用系统粗体完成实现并说明字形差异。

原作 `--u=min(1vw,1.7778vh)` 适合横屏构图，但手机操作与正文要保留最小像素尺寸、安全区和可滚动区域。竖屏用不拦截操作的横屏提示或重排。长中文、长昵称、更多卡片不能撑坏版式。

持续实现和验证，不在交出方案/提示词后停下。按项目运行方式验证真实数据、核心导航和主要画面，修复控制失效、遮挡、焦点丢失与输入穿透。有工具限制时区分已实现、静态检查与未运行部分。最终简短说明改动屏幕、验证、限制，提供实际文件/预览。
