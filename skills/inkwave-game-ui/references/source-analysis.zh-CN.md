# INKWAVE UI、视觉与交互深度剖析

> 原作研究记录：本文件保留研究版本的配色、位置和数值。v2技能的项目决策以[自适应设计](adaptive-design.md)为准，原作五组配色与深紫/黄绿不构成迁移限制。

研究日期：2026-10-29。对象：[amiaoapp/inkwave](https://github.com/amiaoapp/inkwave)，固定提交 `7c970e65beea8f54ca94d2ac326674e0c2e7279b`。包版本1.1.0，屏幕显示的config.VERSION为1.0.0，二者不同。证据来自完整源码、公开部署的加载/标题/主菜单，以及原仓库UI Lab的实际操作。Lab直接挂载原Menus/HUD/CSS，背景、角色和对局数据为模拟；不能据此声称验证了完整对局或真实联网。声音结论来自源码，并未进行听感测试。

公开部署主菜单实拍显示Turf War/Boss Battle，默认特殊能力Tidal Slam；固定提交的Lab包含Zone Control等不同内容，说明不能假定部署与main源码完全一致。本技能以固定提交的组件和规则为依据，公开画面只佐证视觉语言，不把部署特有数据并入源码事实。

## 1. 核心：活着的墨水、可触摸的街头印刷品

三种语法相互配合：街头贴纸/运动票券提供轻微歪斜、白切边、粗墨色轮廓、硬投影、撕边胶带与印章；液体墨水提供指针处涌入的按钮颜色、液面资源球、滴墨和弹跳；主机游戏的信息结构提供大动作优先、焦点详情、按键图例、稳定返回和持续可见的场景。

因此仅用高饱和色与普通圆角卡片无法还原。字形轮廓、物体层次、输入反馈和预览流程必须同时成立。Splatoon是仓库声明的参照；这里提炼的是INKWAVE可观察规则，不声称掌握Nintendo内部设计系统。

## 2. 精确视觉参数

`u=min(1vw,1.7778vh)`是贴合视口的16:9参考框宽度的1/100。1600×900时1u=16px，1280×720时1u=12.8px。边距、字、圆角、描边、位移同比缩放；它不是固定8px网页网格。

### 字形与层级

标题是Titan One **400**：看起来很厚，但字体字重本来就是400。正文/说明是Rubik 500–900。标题描边.17em、paint-order:stroke fill，底部.085em墨影使字有厚度。不是把普通无衬线一律设bold就能复现。

正文最小字号：xs=max(11px,.8u)，s=max(12px,.95u)，m=max(13.5px,1.1u)，l=max(16px,1.4u)。普通按钮文字约1.7u，主菜单大按钮3.6u；普通菜单条约4.5u高、大按钮7.6u高。部分后加组件仍有更小字号，窄屏需修正。

**中文迁移建议**：用合法的圆黑/粗黑900，标题描边约.07–.12em、行高1.1–1.2，正文500–700；不把英文字母的.12em/.24em字距直接套长中文。这是迁移建议，非原作中文规格。仓库附带的是Latin字体子集，不含汉字。

### 两种表面

**墨水玻璃**用于普通菜单、属性、设置：深紫渐变rgba(38,31,58,.9)→rgba(18,14,30,.92)，圆角1.5u，内细白边、顶部微高光、.45u实影和软阴影，blur14px/saturate1.3。一角网点逐渐淡出，保留场景空间。

**实体贴纸**用于联机hub/lobby、模式卡、新闻等：白切边.16u→墨外圈.42u→右.42u、下.52u硬投影；不透明底，常见±1–3°角度、-2°黑胶带、-45°斜纹、低对比颗粒、滴墨。大厅源码明确将其与普通玻璃面板区别。

图标是厚实SVG轮廓与实形：墨滴、武器、齿轮、时钟、箭头、徽章统一厚度。大飞溅集中于标题、卡角、关键动作；数据表和正文保持安静。不要全屏到处添加高对比噪声。

## 3. 各屏幕如何组织注意力

### Loading / Title

加载页中央Logo+双色飞溅，粗边胶囊进度条里有斜纹和高光，右侧百分比，底部单条Tip；深紫背景叠队色光晕和网点。品牌、进度与等待价值各占一个层级。标题页Logo在约40%高度，开始提示距底约15%，轻呼吸；首次输入低门槛进入，不把所有功能堆到标题屏。

### Main

左侧约30u纵向菜单，PLAY最大；ONLINE有独立色、说明、LIVE徽标；装备、外观、设置、教学、制作名单更窄。右上资料/等级/XP/战绩，右下当前配置，中央留给场景或角色。底部按键图例独立成胶囊。

焦点按钮回正、右移.7u、scale1.045，墨水从输入来源涌入；图标约-8°/1.12倍。非焦点仍微歪。选择感由位置、色、大小、描边共同表达。

### Mode / Setup

先选玩法，再选场景与时段。模式卡用大插画、黑胶带、队色、行动标。选场左侧25.5u图片票券，右侧大场景预览带白黑边，底部武器/外观/START快捷块。日夜开关在预览右上，有太阳/月亮和DAY/DUSK文字。

地图改变同时影响大图、背景色调、名称、描述、小地图和开局摘要，让选择后果可见。日夜图片裁切扫过，卡片有视差/微倾/掠光。地图增多需票券区域滚动，不能复制早期“三张图”布局。

### Loadout

左上图标网格，下方属性、主武器说明、副武器/特殊能力，右侧角色预览和试用入口。列数按数量变化：≤4按数量、5–8用4列、9–12用6列、更多用5列配紧凑布局，不能任何项目固定六列。

focus是正在查看，equipped是已提交。焦点更新属性与数字、显示已装备基准的灰色ghost条和增减数；确认才调用setLoadout。卡片上对勾与焦点外圈不同。迁移可映射角色、技能、卡组或赛车，不一定存在武器。

### Locker

左侧分页样式方块和色样，右侧持续可见角色；选择后保存、角色变化、已保存提示、轻飞溅。预设/随机/发型/帽子/眼睛/皮肤/服装都是小卡。换页将焦点放到已装备项，避免失去方向。角色是结果展示而非无关装饰。

### Settings

分页、设置行、底部帮助和重置；说明随焦点。分段用一个真实滑动的胶囊，滑杆大圆把手+数字+扩大拖区，开关文字与颜色同步。拖动时即时写值，结束再恢复轻补间。

音量、FOV、反转、画质、色觉等有相应示意，让抽象值可感知。迁移优先接真实效果，不能用好看却与实际值脱节的示意冒充预览。

### Pause

背景定向压暗、去饱和/模糊，左菜单、右对局/装备/操作摘要。训练模式换装、重置、换图后可直接继续，路径更短。在线暂停明确比赛仍运行，不能让玩家以为时钟停止。

### Results

先胜负和角色时刻，随后统计升起；双方占比/贡献是主证据，再逐行数值、奖章盖章、XP分段增长和升级停顿。顺序是情绪→解释→下一步。

原作键盘/手柄第一次accept在动画未完时只finish，显示全部最终值，不顺便开下一局。鼠标点空白也可跳过，点击真正按钮有自己的语义。该规则比“有计数动画”更值得移植。

### Online Hub / Lobby

入口分CREATE与五格JOIN CODE，右侧名牌/配置；房间里房码、人数/双方名额、玩家队色、ready和开始条件清晰分区。荧光行动色独立于队色。空位、机器人、未准备、已准备、房主与访客用不同文字/徽章。

房主编辑、访客读结果和权限提示。连接失败有“找不到房间/满员/正在比赛/无法连接/连接丢失”分别解释与恢复建议。这里只在netmock=1观察模拟房间，没有创建外部真实房间或邀请任何人。技能不自动添加联机服务。

## 4. HUD：周边信息簇、中央战斗空间

顶部中央时间，两侧成员徽记；死亡有叉、去饱和与复活倒计时环，本人箭头。右上液体球充能、副能力成本徽章、涂地数，事件feed沿右侧；资源、地图、准星、临时横幅各自成簇。

≤60s末分钟状态，≤10s危险底色和逐秒弹跳。能力满时一次ready爆发、持续可用环/射线和按键提示，不只是发光。成本不足、命中、目标、蓄力、死亡都有局部反馈，不把每个事件变成全屏震动。

Tab/M按住地图时，完整游戏相机升起为立体地图并显示队友跳跃点；这需要相机/世界/HUD协同，不能当通用CSS特效。非射击游戏可以借用“按住查看、松开返回”，不硬加超级跳跃。

层级参考：HUD10、触控15、菜单20、覆盖30，游标在所属层内50。它表达关系，不要求把z-index原封不动复制。装饰/常驻HUD通常透过指针，实际可操作表面才接收事件。

## 5. 动效与操作节奏

| 事件 | 原作参数 | 作用 |
|---|---|---|
| 入场 | 600ms，spring，40ms+i×38ms错峰 | 依次落位 |
| Logo入场 | 900ms，spring2，从.25倍/-14° | 一次品牌强调 |
| 离场 | 280ms，前进/返回方向相反 | 表达层级 |
| 按压 | .93/.955/.97依组件，回弹约320ms | 挤压触感 |
| 普通焦点 | transform420ms，blob550ms | 抬起和墨水涌入 |
| 选项胶囊 | 450ms，途中宽扁 | 一个选择物体移动 |
| 贝塞尔 | (.34,1.56,.64,1)与(.26,1.9,.5,1) | 轻/强过冲 |
| 游标弹簧 | k260/c20 | 在项目间追随 |
| 轻转场 | 520ms装饰，立即换内容 | 保持操作连续 |

translate、scale与静态transform分离，避免入场/倾斜/focus抢同一个变换。弹簧dt≤.1秒并分步，防掉帧后弹飞。完整泼墨只用于重要边界，普通菜单轻扫。

鼠标实际移动才接管焦点，静止指针不抢键盘。方向键/WASD导航，Enter/Space确认，Esc/Back返回，QE/肩键换页；字段编辑时先处理字符、确认、取消，防止WASD透出。返回记忆各屏焦点，复杂布局显式邻接图，模态独占导航。

音效分ui_hover/click/confirm/back/toggle/slider/error；确认向上、返回向下，滑杆与计数音节流。结论来自音频源码，非听感验证。

## 6. 手机、可访问性与原作局限

触控层明确不使用--u，而用短边计算；JS布局和几何命中共享数据。左侧触点生成移动杆，右侧瞄准，开火按钮可作视角拖动起点。旋转、失焦、菜单打开释放输入，防残留移动/开火。

当前touch.css把早期全屏旋转墙改为不拦截输入的顶部提示。但touch.js仍在portrait时关闭实时控制，不能宣称已完整支持竖屏战斗。迁移需要有效横屏路径，或真正重排并实现竖屏控制。

原作有reduced motion、色觉模式、安全区、部分aria-live、数字等宽；自定义导航把许多button设tabIndex=-1，通用Web照抄有可访问性代价。保留原生button/range/switch、Tab、focus-visible，再叠游戏操作，除非已有完整焦点管理。

1280×720的Lab选场实拍中底部设置接近或超下缘，说明缩放公式不能保证所有内容可达。迁移检验长中文、昵称、更多条目、字号缩放、滚动到焦点；相似度不以复制溢出为代价。

## 7. 复用边界

可迁移的核心是厚字墨边、印刷贴纸层次、有机墨形、清楚的焦点/按压反馈、操作图例与预览/提交区别。原作双队色、深紫玻璃、黄绿行动色、外围HUD和具体弹性参数是参考实现；v2按目标题材、玩法和设备重新决定颜色、位置、材质与强度。

随目标变化：名称、Logo、角色、图标、世界美术、关卡、数值、职业、战斗。单人无队伍时第二色可表对比项；不虚构敌我。卡牌不加准星，平台不加武器轮，竖屏不强制横屏。样例是重建组件，不是原作截图或目标游戏已改好的证明。
