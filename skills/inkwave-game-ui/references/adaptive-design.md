# 自适应设计：从游戏证据到界面决策

这是本技能的设计入口。source-analysis记录原作事实；本文件规定如何为目标游戏做新设计。保持INKWAVE的墨水、粗描边、贴纸与触感，允许题材、配色、版式和动效强度形成每款游戏自己的组合。不会仅凭“恐怖”“经营”等分类名套预设。

## 1. 从项目提取可用事实

按用户明确要求、项目设定/设计文档、可运行玩法与界面、现有美术和代码查明：

| 维度 | 需要知道什么 | 会影响的决策 |
|---|---|---|
| 题材/世界观 | 时间地点、材质、文化/科技、环境色、阵营与符号 | 色系、底材、图标隐喻、装饰语言 |
| 体验目标 | 轻松、紧张、惊悚、竞技、沉浸、幽默中实际希望突出哪些 | 饱和度、明暗、装饰密度、弹性与声音强度 |
| 核心循环 | 玩家最常做什么，操作/决策/等待各占多少 | 首要行动、常驻信息、可折叠内容 |
| 决策时效 | 哪些状态必须即时发现，哪些允许停下来阅读 | HUD优先级、告警、刷新、转场是否打断 |
| 操作与视角 | 触控/键鼠/手柄、横竖屏、第一人称/俯视/棋盘/对白 | 保护区域、触区、焦点图、输入语义、面板位置 |
| 已有约束 | 品牌色、阵营/稀有度/资源映射、字幕、语言、存档和暂停规则 | 必须继承的语义与业务边界 |

从美术推断的情绪不是确立的世界观；写明必要的假设，不把未知故事补成事实。先完成可逆、证据充分的设计。只有缺失信息会阻止正确实施时才集中询问；不要为每个颜色或位置请求批准。用户指定颜色/布局/无动态时按其要求设计。

## 2. 先明确保留项和调整项

| 保留的设计语言 | 随游戏变化 |
|---|---|
| 主标题/关键控件的厚实字形、墨色轮廓与清楚主次 | 字体家族、圆胖程度、字号、中文描边比例 |
| 贴纸切边、硬影、印刷层次与有机墨形 | 切边用白/暖纸/浅灰、面板色、角度、纹理和装饰密度 |
| focus/pressed/selected的触感及可理解反馈 | 过冲、位移、速度、频率；低动态可以静态替代 |
| 预览/提交有区别、动作与结果可追踪 | 提交时点、返回路径、键位，遵守游戏实际规则 |

保持关键屏幕和共享控件有可辨识的INKWAVE家族特征。阴暗题材仍可用墨边票券与淡金封条，温暖题材仍可用深墨轮廓与彩色贴纸；不把风格归结为紫底或荧光色，也不把所有特征降到普通方框和无反馈按钮。

## 3. 为游戏生成语义色，而非挑固定色卡

先从环境/角色/标志中找主色候选，再分配角色。使用任何合适的合法颜色值，原作五组只是可参考的研究样本，数量和色相均不受它限制。

| 角色 | 决策 |
|---|---|
| ink / outline | 结构性深色，按主题偏绿、蓝、褐等，需让切边/轮廓稳定 |
| surface / surfaceAlt | 游戏信息承载底，和最忙/最亮/最暗场景分开检查；透明玻璃按合成结果检查 |
| text / muted | 正文/辅助字，按实际面板选，不能用低透明度让说明消失 |
| primary / secondary | 主题与次强调；secondary可以是对比/进度，无阵营时不虚构对手 |
| action / focus | 执行或导航提示，可复用主色；只有需要区分行动与归属时才增加独立色 |
| danger / warning / success | 根据已有规则定义；冲突时增加明度、形状、文字、边框，保持全游戏一致 |
| faction / resource / rarity | 仅在真实机制存在时增加；不把主题色变化写进游戏阵营或品质数据 |

控制同屏竞争：一个主要行动层级，其他状态按优先级出现。暗面板不必深紫，行动不必黄绿，贴纸边不必纯白。保留已有可理解的警示、阵营和资源语义；不因某个颜色“像恐怖”就把所有按钮和危险都涂成相同红色。

以普通文字4.5:1、大字/关键可视边界3:1作为实色检查起点；再检查实际字号、渐变、透明合成、亮场景和低动态状态。小字不合格时调整填充或前景，而非用描边掩盖。颜色不能是唯一的信息载体。源码的亮度.36阈值仅为参考，主题应用函数也不能替代实际场景检查。

## 4. 按任务、视角与设备重新排版

先给每个已有屏幕列出：玩家现在要完成的任务、一个首要行动、必须同时可见的信息、需要保护的视觉区域。

- 第一人称动作：保护准星/瞄准路径，紧急资源和能力靠近可扫视区域；次信息按需展开。
- 棋盘/卡牌/策略：保护棋盘、手牌、回合与目标关系；选中项详情贴近决策区，可用侧栏或抽屉。密度高时减少倾斜，避免遮牌。
- 经营：常驻核心资源与异常，生产详情分组/筛选/折叠；高频收取路径短，不能每次开新模态或播放长奖励动画。
- 叙事/解谜/探索：保护对白、线索或环境细节，次状态按需出现；阅读区平直、行距足够，墨水贴纸用于标题/选择标签。
- 触控：从可达性和遮挡出发，主操作在合理拇指区，保证滚动与点击不会冲突；竖屏可以底部导航/上方预览。

这些是推理例子。混合玩法按当前屏幕的实际任务组合，不能只凭游戏类型硬选一种版式。原作“左列表、右人物、底部开始”可作为方案之一，位置、比例、锚点和顺序都可变。没有角色展示需求就把空间给棋盘或信息；不为了像原作新增装饰预览。

## 5. 交互按操作成本与失误后果决定

先保留现有业务语义，再做界面优化：hover/focus适合查看，不保存；低风险外观可即时应用并清楚表示已保存；消耗稀有物、不可撤销选择遵守已有确认/撤销机制，不凭风格额外加确认层。

高频动作减少往返，复杂选择给比较和上下文；同一种动作在不同页面的词语、位置关系与反馈保持一致。模态仅用于需独占注意力的情况。键位按项目冲突表与设备决定，不强行沿用原作QE/Tab；地图按住或切换遵循玩法与已有设置。

## 6. 动效按语义调节，不能拖慢决定

分别为导航、即时状态、场景切换、奖励定义强度。不能把一种速度乘数套全部动画：竞技受击信息应即时出现，而奖励可以丰富；恐怖游戏的死亡告警仍要清楚，不能因为“克制”而延后。

可从以下范围开始调试，非原作常量或强制预设：

| 场景 | 可调参考 | 保留的可感知反馈 |
|---|---|---|
| 精确操作/长阅读/紧张探索 | focus约120–240ms、位移0–4px、scale1–1.02，低过冲 | 墨边、颜色/标签、短距离填充和局部按压 |
| 活泼休闲/竞技菜单 | focus约200–420ms、位移4–10px、scale1.02–1.045 | 适量墨水涌入、弹性和错峰 |
| 庆祝/解锁/章节边界 | 允许更强盖章、飞溅或一次性转场 | 可跳过、最终状态完整、不影响业务入账 |

压缩频繁循环、缩放文字和全屏闪动；静态选中标记始终存在。减少动态覆盖所有题材配置，去视差/大位移/旋转/循环，保留可见状态。触区与命中不因装饰缩放漂移。

## 7. 生成可实施的项目决策

规模适当时在项目已有设计文档记录下面结构；小改动在工作说明中给相同要点即可。不要求用户逐项填写，也不等待额外批准。

```text
依据：用户设定/设计文档/玩法代码/现有画面的关键事实；必要假设。
体验与约束：期望情绪、高频操作、设备、保护区域、已有色彩语义。
颜色：角色→实际值→用途/理由，含警示和选中如何分辨。
布局：各屏核心任务→信息优先级→位置/密度/窄屏方案。
交互：查看/提交/返回/取消/保存时机，焦点与输入归属。
动效：各类反馈强度、时长/位移依据、低动态替代。
保留：哪些可见特征仍属于INKWAVE；验证：实际场景与尺寸。
```

assets/theme-profile.example.json是虚构“夜巡探索”项目的示范，不是读取任意项目后都应采用的答案。Web的applyInkTheme应用颜色与动效部分，布局/业务部分由Codex修改目标项目组件或场景。测试/展示几个主题不代表它们成为新的固定菜单。

实现后用实际画面与主流程复核：设定相关性、信息清楚、操作成本、风格辨识均成立；如果只换色而遮挡关键玩法，继续调整。最终简短说明设计依据和实现验证，避免声称主观设计判断已由格式检查证明。
